## 6. Deployment-window prerequisites

### 6.1 Reconcile the Alembic branch point — **the one that stops the deploy dead**

The node holds `7ed2a670841e`, an empty no-op that exists nowhere in git and revises `3a65a83e0463` — and
so does `b7c2e9a41d38`, the release's first migration. Two heads; `alembic upgrade head` refuses;
`startup.sh` makes that fatal, so `report-api` would never serve. **Runbook §1.2a.** Re-read the head first:
every restart of the currently deployed stack mints another one.

### 6.2 Push and merge

Both branches are local. `ifet-management` must reach `latest` before the window.

### 6.3 The DG14 gate changes operator-visible behaviour on the day

An Airtable-imported static or cyclic job with stages still to run **stops** until its design-pressure pair
is verified. Runbook §2.1 — agree beforehand who does that, and how. There is no screen for it yet
(TC5 **Screen 2**).

### 6.4 Rig Static Load and Cycles need an operator declared at run start

`attempts.complete_rig_trial` will not terminate a rig-posted stage with no operator, and the rig has no
operator to give. The declaration is one optional body on a call the **existing** Static/Cycles run screens
already make:

```
PUT /projects/{project_id}/static_tests/{static_test_index}/start   body {"operator_name": "…"}
PUT /projects/{project_id}/cyclic_tests/{cyclic_test_index}/start   body {"operator_name": "…"}
```

`static_tests/…/start` is **new in this release**; `cyclic_tests/…/start` exists in production but accepts
no body there. **This is a change to the existing screens, not a TC5 screen** — TC5's five are job picker ·
requirement release · manual test (Forced Entry + ANSI) · impact · sync status, and its §9 says no second
interface for Static Load and Cycles is to be built. See TC5 **§9.1** and runbook **§2.2**.

Without it a rig attempt stays `In Progress`: the row is created in Airtable and sits at `Pending`, and the
reason is visible in `GET /sync/failures`. Nothing is lost — it completes as soon as an operator is
supplied. **Never default the name.**

### 6.5 The runbook's own gates

§1.4 rehearsal against a restore of the real dump · §1.5 open-Impact-attempt gate · §1.10 GO/NO-GO.
