Every release-relevant finding on record, classified against **current** evidence rather than carried
forward on its original wording. Four classifications, and the third is not a euphemism for the first:

| | |
|---|---|

## 1. Airtable and contract

### 1.1 The proposal extraction defect — **ACTIVE, and escalated today**

Source: `live-probe-findings-2026-08-23.md` §5.2 · contract legacy item 19 · plan **DG14**.

Their PDF extractor reads *values in order* rather than *values by column*, so a blank cell slides
everything after it one place left and a 60 PSF requirement arrives as 9.

**Previously classified as removed from the execution path by A9. That classification is wrong and has been
corrected.** LabOS has read `Required Value Inward` / `Required Value Outward` since 2026-09-08 and derives
all fourteen static and cyclic stages from the pair. A shifted pair is a shifted test.

| | |
|---|---|
| Blast radius | Static Load and Cycles, for any Airtable-imported job |
| Out of it | **Impact**, since TA7 — a pick from a closed set of three cannot shift a column. Forced Entry and ANSI have no numeric requirement |
| Owner | the extractor is Airtable/IFET's; the compensating control (contract §3.3) is LabOS's and **does not exist** |
| Verification required | either the extractor is fixed and re-verified upstream, or §3.3's operator confirmation is implemented and made mandatory on import |

**No heuristic was added and none should be.** Every shifted value is individually plausible.

### 1.2 `Inches` vs `in` unit divergence — **RESOLVED**

The envelope refused their spelling. `requirements.UNITS_BY_KIND` now carries the units actually in the
base, `Required Unit` is read for validation only, and a unit that contradicts its kind is refused rather
than assumed to be PSF. Covered by `test_a_unit_that_contradicts_its_kind_is_refused`.

### 1.3 `Abborted` misspelling in their base — **RESOLVED by accepting it**

`contract.Field("Test Status", option_wire={"Aborted": "Abborted"})`. LabOS keeps its own spelling
internally and sends theirs verbatim, because a single-select will not accept ours. Confirmed against both
live bases today.

### 1.4 A PAT leaked in an Airtable-team PDF — **NOT RELEASE-RELEVANT to this deployment, still owed upstream**

Recorded 2026-07-29. Nothing in this repository holds it; `check-secrets.sh` passes. Rotation is theirs.

## 2. Database and migration

### 2.1 Migrations autogenerated at every container start — **RESOLVED**

`startup.sh` used to call `command.revision(autogenerate=True)` before every upgrade, so a `models.py`
change reaching the node would alter the production schema at the next restart with nobody in the loop. It
now **applies migrations and never invents them**, and a failure is fatal rather than swallowed.

### 2.2 `alembic/versions` gitignored, chain only on the node — **RESOLVED**

All **38** revisions are tracked in git today (`git ls-files … | wc -l` → 38, and `git check-ignore` does
not match). The directory is still bind-mounted, so the files must be in the node's working tree at
container start — the runbook says so.

### 2.3 The repo is not ground truth for the deployed revision — **ACTIVE, by design**

Still true and still the rule: `SELECT * FROM alembic_version;` **on the node**. Recorded as
`3a65a83e0463`, which is position 29 of 38, so a deploy applies nine migrations. First item of the
runbook's pre-deploy checklist.

## 3. Firmware and the rigs

All of §3 comes from `firmware-production-runtime-contract-2026-08-31.md`. **This release changes no rig
code**, so none of these is caused by it; what matters is whether any of them changes what the release
should claim.

### 3.1 Firmware derives nothing; it posts deflection triples and nothing else — **NOT RELEASE-RELEVANT**

This is the architecture, not a defect, and the contract is written to it: management owns 100% of
derivation. It is why the outbound payload contains no rig-measured pressure, duration or cycle count.

### 3.2 `recovery` is a config constant (60), not a measurement — **RESOLVED by omission**

All 609 firmware-written deflection rows carry `recovery = 60` verbatim from `recovery_time`. It is never
published as an observation because **no deflection data reaches Airtable at all** — `Deflection Value`,
`Deflection Unit` and `Max Pressure Achieved` are the three fields preflight reports as *withheld*, and
their absence is the decision rather than an oversight.

### 3.3 SICK gateway truncates deflection to the first two bytes — **NOT RELEASE-RELEVANT, tracked as M6**

Values cluster at ±32700, the signed-int16 boundary. Firmware does no deflection arithmetic. Quarantined,
and nothing quarantined is exported. Bench calibration is hardware-side and blocks nothing here.

### 3.4 473 of 1082 deflection rows are synthetic seed data — **NOT RELEASE-RELEVANT**

Historical local data quality. Not exported, and no migration in this release reads or rewrites it.

### 3.5 Static tests have no automatic pressure control and no timeout — **ACTIVE, NOT RELEASE-RELEVANT**

`HoldingTimeState` waits for `abs(sensor) > abs(setpoint)` and never commands the VFD; an unreachable
setpoint blocks the state machine indefinitely while an operator ramps the blower by hand. Real, unchanged
by this release, and on the record. It is a rig-safety item for the firmware backlog, not a gate on a
management deployment.

### 3.6 The cyclic loop's control is commented out — **ACTIVE, NOT RELEASE-RELEVANT**

Measured 2.021 s/cycle against two 1.0 s sleeps; `low_pressure` affects only the initial ramp. Same
classification and same reason as §3.5.

### 3.7 The two production rigs run different firmware, and `system-1` is misconfigured — **DEPLOYMENT-WINDOW VERIFICATION**

As at 2026-08-31: `states/idle.py` differed on `system-2` (the RELIEF guard — the valve-3 stuck-open fix —
had not reached it), and on `system-1` `state_machine`/`valves_service` were bind-mounted on
`config1-site-b.json` while `serial_service` used `config1.json`. The valve-3 fix is recorded as deployed
to `system-1` only. **Not verified from this session** — it needs the fleet, and this release does not
touch rig code.

```bash
# at the window, read-only, per rig
docker inspect --format '{{json .Mounts}}' <container> | jq .
docker exec <container> md5sum /app/states/idle.py
git -C /home/labadm/ifet-firmware log -1 --format='%H %s'
```

### 3.8 Deflection acquisition down fleet-wide since 2026-08-29 — **DEPLOYMENT-WINDOW VERIFICATION**

Both SICK masters unreachable, 45 861 consecutive failures, no success in the retained log. Any test run
since records `deflections: []`. **Not verified from this session.** It does not affect what this release
publishes — deflections are withheld — but a static or cyclic test that records no deflections produces
very little local evidence, so its current state belongs in the deployment record.

### 3.9 VFD Modbus address is per-rig (`system-1` = 12, `system-2` = 5) — **RESOLVED, and the correction stands**

An earlier note generalised `12` to the fleet. Verified per-rig live on 2026-09-08. Recorded here because
the generalised version is still quotable from older documents.

### 3.10 The `test` node has been offline since ~2026-07-24 — **ACTIVE, external**

There is **no non-production rig** to rehearse a rig-affecting change on. This release does not change rig
code, so it is not a blocker for it — but it is why the migration rehearsal runs on a disposable Postgres
rather than on a test node, and it remains an open ask to the manager.

## 4. LabOS runtime

### 4.1 `127.0.0.1:1883` / `:8000` are **production** under the tunnel — **ACTIVE, and a standing trap**

With `ifet-management-tunnel.service` active, localhost is the production broker and API. The simulated rig
under `simulation/ifet_device_node/` carries `system-1`'s own `device_id`. Use `simulation/mf_harness/`.
Unchanged, and it applies to anyone testing around this deployment.

### 4.2 A test with an injected transport is not evidence about the wire — **RESOLVED as a practice**

The rule that produced both live probes. TA7 64/64 and TA6 97/97 run the real chain with the real client;
the local suites keep their injected transport for what it is good at.

### 4.3 `openapi.json` went stale against the running app — **RESOLVED today**

Two routes live and missing from the committed snapshot while the UI developer read it as the contract.
Regenerated, and gated by `TheCommittedApiContractIsCurrent`.

`manual-tests`, `impact-tests`, `ANSI Z97`, `Forced Entry` or `sync/status`. The UI source is not in this
repository. Now also carries DG14's §3.3 verification, which has nowhere to live either.
